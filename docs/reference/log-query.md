#### High priority — Shared deterministic Ollama log-query tool (complete; review conditions resolved)

**Human request, 2026-10-25:** give all agents a shared tool to query Ollama `server.log` deterministically without dumping the entire file into context and wasting tokens. A familiar CloudWatch-like interface is desirable, but exact compatibility is unnecessary. This is a high-priority item, ahead of optional pickup ergonomics.

**Status and authority:** Implemented by OpenCode on2026-10-25 at explicit human direction: “implement it now, then commit and notify GPT-6 in your message that it will review it etc.” This overrides the earlier pre-implementation review gate for this tool only. It is not a GPT-6 approval, verdict or adoption certification. The human requested the retrospective evaluation in this Codex chat; its actual verdict and limits are recorded below.

**Delivered interface:** `uv run globe ollama logs query [options]`, a Pydantic v2 `CliApp` bridged into the existing argparse CLI. The default source is `~/.ollama/logs/server.log`. Output is structured JSON only. The query is read-only, has no follow mode, orders events by source byte offset, uses inclusive `--since` and exclusive `--until` bounds, compares timestamps in UTC, interprets naive timestamps with `--assume-tz` (default `local`), and supports literal `--include`/`--exclude`, `--level`, `--component`, `--status`, `--method`, `--field KEY=VALUE` and `--parse-status`. Missing fields do not match. Bounds: `--limit`1–500, `--max-output-bytes`, `--max-scan-bytes`, `--raw-bytes` and `--context`0–5. Reports include the normalized query, source identity/size/hash, rotation siblings, counts, truncation/completeness, output and scan-cap state, warnings, evidence per event and an opaque `next_cursor`. Cursors pin path/device/inode/size/head hash/prefix hash and reject rotation, shrink or a changed prefix while allowing appends. Unreadable or invalid requests return a JSON error on stderr with exit2; no matches return exit0. Malformed, blank and continuation lines are counted, not silently discarded. Arbitrary log text is treated as data; the tool makes no model calls, does not upload logs, and does not alter/truncate/rotate source logs.

**Original minimum contract considered:**

- A local, read-only interface usable by Codex, Claude, OpenCode and other harnesses, with structured JSON results. Prefer a small CLI/API; evaluate whether an MCP adapter adds value rather than requiring one. No AWS dependency or full CloudWatch query-language clone.
- Query an explicit time window with documented timezone and boundary rules; support literal include/exclude text and fields actually present in the logs, such as level, component, model, process, route or HTTP status. Missing fields remain unknown. Provide compact event retrieval and deterministic counts/summaries; do not invent request correlation or token usage from unrelated generation statistics.
- Enforce default and maximum event, byte and output limits, bounded optional surrounding lines, field projection and pagination. Return the normalized query, scanned scope, counts, truncation/completeness status and continuation cursor. Distinguish no matches from unreadable input, incomplete scans and parse failures. No unbounded dump or follow operation.
- Define stable ordering and tie-breaking using source offsets, and pin pagination to a file identity/snapshot. Handle appends and rotation explicitly: detect stale cursors or gaps instead of silently dropping, duplicating or mixing events. Bound scan work as well as response size; add indexing only if justified by measured need.
- Preserve evidence per returned event: source identity, byte offset or line reference, original timestamp and optionally the selected raw line within the output cap. Record parser version and snapshot/hash provenance sufficient to reproduce or explain a result after rotation. Support actual mixed Ollama log formats without silently discarding malformed or multiline records.
- Make shared agent guidance use the approved tool first for routine log inspection, with narrowly bounded fallback reads only for unsupported cases. Do not load models, call inference, upload logs, restart the server, or alter/truncate/rotate source logs. Treat arbitrary log text as data, and avoid unnecessary secret-bearing output.

**Essential versus optional:** retain the local read-only CLI, literal/time/field filters, JSON evidence and pagination. Essential corrections are a hard serialized-response budget (including parsed fields/metadata), explicit progress or a terminal error for oversized records, and one coherent file/snapshot policy for scanning/context/cursors. Add meaningful regression cases for these failures and rerun `make gate`. A compact projection/count-only mode would better serve the token-saving goal but is a follow-up interface refinement; avoid a CloudWatch language clone, indexing service or MCP adapter until demonstrated need. The existing normal-path tests and historical384-test gate do not establish the missing edge guarantees. Snapshot/provenance accuracy, parser drift, output inflation and no-progress loops remain the concrete risks. Those were the review’s required corrections; their completed resolution is recorded next. No change to P0 or model-workload authorization.

**Correction closeout, 2026-10-25:** all three retrospective conditions are resolved with41focused tests and full397-test gate. Complete serialized responses, including JSON metadata/cursor/newline, must fit `--max-output-bytes`; trailing events are moved to the next page, and an event/metadata/indented response that cannot fit returns a small JSON error (exit2) before any stdout. Parsed messages/fields cannot bypass the cap. Records exceeding the fixed1MiB line cap return terminal `record_too_large`; a scan budget unable to consume even the next record returns `scan_budget_too_small`, never an unchanged cursor. Reads, context and cursor hashes share the open descriptor, scans stop at its opening size, and detected concurrent file changes return `source_changed` rather than a mixed report. Append between queries remains allowed/reported; append during a query is rejected without automatic retries. This uses ordinary file identity/size/mtime checks, not a filesystem snapshot or protection against deliberate same-metadata tampering. v1cursors must be restarted after the parser v2 bump. Oversized errors deliberately require a larger allowed budget or a narrowly bounded fallback; no silent skip or lossy evidence substitution. A large malformed-record regression also exposed and fixed a quadratic unanchored logfmt search. [Closeout evidence](../../artifacts/ollama-log-query-fixes-20261025-01/README.md) retains bounded real-log pages (3,710/3,713bytes under8,192), original offsets and full gate. No new service, model request, log mutation or corpus edit. The local CLI scope is complete; projection/count-only refinements remain optional, not outstanding review conditions.
